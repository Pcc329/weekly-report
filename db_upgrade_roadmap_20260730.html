人力評估:從單人 AI 協作到小型團隊

目前全案由 1 人以「人機協作」模式推進(Claude 規劃/Codex 開發/GPT 覆核)。AI 協作可放大單人產能,但無法取代維運值班、資料治理與跨單位窗口——這是各階段增員的原因。

現況模式的優勢

  • 開發成本極低:規格→開發→覆核全流程 AI 協作,單人可維持正式團隊的產出節奏
  • 決策快:無跨人溝通成本,適合功能仍在快速調整的試營運期

現況模式的風險(需向上揭露)

  • 單點風險:全案知識集中在 1 人,人員異動即斷線
  • 無備援值班:系統異常只有 1 人能處理
  • 建議:階段二起培養第 2 位熟悉流程的同仁(0.2 兼任即可起步)

AI 協作「能抵」的人力

  • 程式開發與修改(Codex 執行)
  • 規格書、測試計畫、文件撰寫
  • 批次資料標註與清理(AI 批次作業)

AI 協作「不能抵」的人力

  • 系統維運與異常值班(階段三起需 0.5 人)
  • 案例知識庫的內容把關(需領域判斷)
  • 跨院窗口、合約與資安法遵溝通(階段四)

關於 MCP:讓其他 AI 系統直接取用智庫的「標準插座」

MCP(Model Context Protocol)是 AI 業界的開放標準。白話說:現在別的單位要用我們的資料,得「走進我們的店裡」(開網頁操作);裝上 MCP 之後,他們自己的 AI 助理可以直接插線到我們的智庫,即問即答——這正是階段四「中央廚房供應分店」的技術基礎。

為什麼現在不做

  • MCP 本身不難,難的是被接取的資料庫要先夠穩
  • 遷移完成前接 MCP = 在未定案的地基上拉管線,之後要重做
  • 因此採「條件觸發制」,不排固定時程

做了以後的價值

  • 他院顧問在自己的 AI 工具內即可查詢本智庫方案與案例
  • 政府標案簡報中「AI 原生智庫」的差異化亮點
  • 一次介接、多方可用,取代逐案客製 API 的開發成本
觸發條件 1
案例知識庫成形,出現「跨多資料源的 AI 查詢」需求
觸發條件 2
Supabase 遷移全數完成並穩定運行(階段二完成)
觸發條件 3
有合作單位正式提出跨系統整合需求(通常出現在階段三後期至階段四)
  • 任一條件成立即啟動評估
  • 導入工作量估:2–4 週開發 + 1 個月試運行
  • 主要成本為人力;MCP 為開放標準,無授權費用

結論三點建議

  1. 階段二的實際新增預算接近零:全成本月費約 NT$3,000–3,500,但其中開發訂閱(約 1,360)現在已在支付,而遷移是把 Airtable(約 2,300)換成更便宜的 Supabase——淨增量幾乎為零,甚至可能省錢。這是「順便省錢的地基工程」,建議優先核可;同時指派 1 位 0.2 兼任同仁,開始分散單人風險。
  2. 階段三啟動前,先確認「案例知識庫」的內部結案報告來源:這是本平台的長期護城河(獨有資料),比任何硬體升級都更決定智庫的價值;人力上需預留 0.5–1 名資料治理角色。
  3. 階段四採需求觸發制,不預先編列大額預算:待有明確的跨院使用方後,再啟動主機選型與資安檢測詢價;屆時可將部分成本設計為使用院所分攤。

  • 人力:1 人(PM 兼 AI 協作)

資料庫與伺服器

  • Airtable(免費/低階方案)+ Vercel 免費方案
  • Supabase 遷移:三大表 API、資安基線、資料同步均已完成;僅餘正式切換前自動化測試(2026-08 更新)

資安現況

  • API 金鑰僅存於平台環境變數,不進版本庫
  • 預覽環境有部署保護(需登入)
  • 聯絡人個資僅內部可見

費用(全成本月費約 NT$4,000)

  • 資料庫:Airtable 約 2,300(佔比最大)
  • 開發:Codex + Claude 訂閱 約 1,360
  • AI 推論:Claude API 約 400(試測規模)
  • 代管:Vercel 免費方案 NT$0
升級判斷點:①試測顧問回饋正向、有明確省時案例 ②Supabase 遷移完成並通過逐筆比對驗證。兩者達成才進入階段二。

階段二.固定店面:院內組級推廣

短期 0–3 個月|目標:完成資料庫「換心臟」,服務擴大到 10–30 人;重點投資是資安分權,不是硬體

使用對象與人力

  • 院內相關組別顧問 10–30 人,純內部
  • 人力:1 人專責 + 0.2 兼任(資料維護/使用者窗口)
  • 兼任者同時作為第 2 位熟悉全流程的備援

資料庫與伺服器

  • Supabase(PostgreSQL 正式關聯式資料庫)
  • 資料量在免費額度內,但建議 Pro:每日自動備份 + 不休眠保證
  • Vercel 升級 Pro,符合非個人用途條款

資安評估(本階段重點)

  • 金鑰分權:查詢用受限金鑰、管理另用管理金鑰;單一金鑰外洩 ≠ 全庫外洩
  • 資料列權限(RLS):資料庫層級控管誰能看什麼
  • 聯絡資訊遮罩:一般使用者看到的聯絡人資料經遮罩
  • 個資盤點:確認聯絡人資料蒐集依據與利用範圍(個資法)

費用估算:全成本約 NT$3,000–3,500/月

  • 資料庫:Supabase Pro 約 800 + Vercel Pro 約 640
  • 開發:Codex + Claude 訂閱 約 1,360(續用)
  • AI 推論:隨人數微增(數百至一千元)
  • 關鍵:總額比階段一還低——Airtable(約 2,300)退場、換成更便宜的 Supabase,遷移的「淨增量」接近零甚至為負
升級判斷點:①穩定使用滿 1–2 個月、無資料正確性客訴 ②有 10 人以上實際使用數據佐證價值 ③案例知識庫開始累積。達成後才值得投資階段三。

階段三.旗艦店:院級正式服務

中期 3–9 個月|目標:從「好用的工具」升級為「說得出口的正式服務」,可作為 B2G 智庫資產展示;MCP 評估在此啟動

使用對象與人力

  • 數轉院內 50–100 人;院內其他單位可申請使用
  • PM 1 人(產品與跨單位溝通)
  • 資料治理/案例知識庫 0.5–1 人(內容把關需領域判斷,AI 無法全代)
  • 技術維運 0.5 人(異常處理與值班,可兼任)

資料庫與伺服器

  • Supabase Pro 續用,加購時間點還原(PITR)強化備份
  • Vercel Pro + 正式自訂網域(提升對外簡報可信度)
  • 資料治理:206 筆 AI 標註補齊、欄位命名統一

資安評估

  • 登入機制:院內信箱登入或 SSO,取代連結制
  • 稽核紀錄:誰在何時查了什麼,留存 log 備查
  • 備份還原演練:每季實際演練,不只「有備份」
  • 對齊資策會內部資安規範,先做內部自評

費用估算:全成本約 NT$5,000–6,500/月

  • 資料庫:Supabase Pro + PITR + Vercel Pro + 網域 約 2,200
  • 開發:Codex + Claude 訂閱 約 1,300(開發趨緩)
  • AI 推論:隨 50–100 人成長(估 1,500–3,000 元/月)
升級判斷點:①有明確跨院需求方(至少一個院所表達採用意願) ②院方同意投入階段四資安檢測預算。沒有確定的外部需求,就不進入階段四——整條路線圖最重要的煞車。

階段四.中央廚房:跨院/對外 B2B 服務

長期 9–18 個月(需求觸發)|目標:供應其他院所使用;一旦對外即有 SLA 與正式資安要求,主機選型在此才做最終決定

使用對象與人力

  • 100 人以上;他院透過帳號或系統介接(API/MCP)使用
  • PM/產品 1 人
  • 維運工程 1 人(選項 B 自建機房須專職)
  • 資安/法遵窗口 0.5 人
  • 導入支援/客戶窗口 0.5–1 人

主機三選項(屆時擇一)

  • A. 商用雲端(GCP/AWS/Azure 台灣區):彈性最高、上線最快;月費約 1.5–4 萬;適合需求量不確定時
  • B. 院內機房自建:資料完全在院內,資料主權最嚴格;需一次性硬體投資 + 專職維運
  • C. 政府雲(如 TWCC/公務雲):法遵路徑最順,適合政府標案情境;採購流程較長
  • 初步傾向:客戶以政府相關院所為主 → C 合規優勢最大;速度優先 → A 先行、C 為終點

資安評估(對外門檻)

  • 資通安全管理法適用性評估:確認對外後的資安責任等級
  • 弱點掃描 + 滲透測試:委外執行,一次性估 NT$15–40 萬(需正式詢價)
  • 個資去識別化政策正式化;與使用院所簽訂資料使用協議
  • SLA 承諾(可用率、故障通報時限)與值班機制
