資料庫切換完成報告

✅
切換完成，系統運作正常。Production 資料來源已由 Airtable 正式切換至 Supabase，六項驗收全數通過；前台與 AI 功能運作照舊、使用者無感。回滾機制就緒，零資料損失。
切換日期：2026-08-12（三）上午 對象：solutions / companies / cases 三支 API 狀態：已進入三個月觀察期

一、誰動了、誰沒動

本次切換只換了「資料從哪來」。前端與 AI 功能本身沒有搬移，仍在原地運作——這是切換對使用者無感的原因。

前端（網頁）
沒搬。同一個網站、同一網址；只是取得的資料改由 Supabase 提供，使用者無感。
API（中間層）
改了資料來源。solutions / companies / cases 三支改向 Supabase 撈，不再走 Airtable——這是本次切換的實際內容。
LLM（AI 功能）
本身沒搬，原料換了。AI 一直呼叫 Anthropic API，與資料庫無關；只是分析／推薦時讀的方案資料現在來自 Supabase。
使用者 → 前端（Vercel，沒搬） ↓ 呼叫 API（改了來源）→ 現在撈 Supabase ✅ ↓ 提供資料 LLM（Claude API，沒搬）→ 拿 Supabase 的資料分析
一句話：

唯一換掉的是最底層的資料倉庫（Airtable → Supabase）。上層前端、API、LLM 都在原地，只是「進貨來源」換成更穩定、更省成本的 Supabase。

四、為什麼可以放心

可逆設計 + 三個月觀察期
