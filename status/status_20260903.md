### PR #8：封存清單路徑相容層

- 問題：`index.html`、`statusUpdate.html`、`weekly.html` 皆呼叫 GitHub Contents API 掃描根目錄再以檔名正則過濾，檔案移入子資料夾後清單會失效
- 做法：改為同時掃描根目錄與對應子資料夾，以 `Promise.allSettled` 合併，子資料夾不存在時安靜降級
- 每筆結果同時保留 `name`（供正則比對與日期解析）與 `path`（供 fetch 與連結）
- **審查發現**：`index.html` 兩處 catch 區塊回傳物件缺少 `path`，抓取失敗時連結會產生 `reader.html?file=undefined`，屬本次改動引入的迴歸，已修正
- 4 個 commit，合併後行為與改動前完全一致

### PR #9：檔案搬動歸類

- 刪除 2 個改檔名時殘留的重複檔（md5 驗證內容一致）
- 搬移 59 個檔案至六個資料夾，使用 `git mv` 保留檔案歷史
- 更新 `index.html` 18 條硬編碼連結、19 支 docs 頁面的 `../nav.js` 與 `../index.html` 相對路徑、status 與 report 內的絕對連結
- **審查發現兩處遺漏**：
  - `docs/freshness-audit.html` 的 reader 連結未加 `../` 且未指向搬移後的 `/sop/`
  - 同檔案內 URL 編碼形式的 GitHub blob 連結（`codex_%E8%A6%8F%E6%A0%BC...`），Codex 以中文檔名搜尋無法命中
- 3 個 commit

## 三、本次審查的兩點經驗

1. **Codex 的自我檢查有盲點**，兩次皆回報「已確認無遺漏」，但實際 diff 掃描仍找得到問題；以 raw diff 驗證而非採信口頭回報，此原則再次證明有效
2. **URL 編碼連結是搜尋盲區**，中文檔名在 HTML 中會編碼為 `%E8%A6%8F...`，以原文搜尋必然遺漏，檢查時應改用 `blob/main/` 這類結構性關鍵字
